AutoVQE

A minimal, reproducible harness for hardware-aware VQE — fixed wall-clock budget, one editable file, one log.

Problem

VQE benchmarks are usually iteration-bound. That makes them easy to publish and hard to compare honestly: a method that converges in fewer iterations may still be slower in practice — gradient evaluation, transpilation, classical-optimizer overhead, hardware noise all bite differently.

What I wanted instead was a harness where every run is given the same problem-dependent wall-clock budget and judged on what it produces inside that envelope.

Contribution

A single-file research harness that fixes wall-clock at 2^(n−2) seconds for an n-qubit problem, hands the experimenter a single editable train.py, and logs every run as a row in results.tsv. The rest — Hamiltonian preparation, transpilation, evaluation utilities — is deliberately frozen.

$$ \min_{\boldsymbol{\theta}} \; \langle \psi(\boldsymbol{\theta}) \,|\, \hat{H} \,|\, \psi(\boldsymbol{\theta}) \rangle \quad \text{s.t.} \quad t_{\text{run}} \le 2^{\,n-2} \text{ s} $$ Eq. 1 — VQE under a fixed wall-clock budget per problem size.

Method

The harness is split into a frozen prepare.py (problem loading, transpilation, evaluation) and an editable train.py (ansatz, initialization, optimizer). Each run logs commit hash, final energy, single-/two-qubit gate counts, parameter count, status, and a one-line description of the change.

Status

Feature-complete on synthetic Hamiltonians; current work is on noise-aware extensions and on driving the loop with a coding agent rather than by hand. A short technical report is planned for late 2026.
